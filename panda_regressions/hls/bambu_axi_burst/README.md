# Classic AXI burst regression

Native Bambu end-to-end and compiler tests live here. Direct RTL tests and
Bambu-generated RTL simulations live in
`panda_regressions/verilog/axi_burst/`; the suite below invokes them from that
location. T4B native Bambu runs remain in this directory's `t4b_tests/`.

Run the suite through `../bambu_axi_burst.sh` with `--group=compiler`,
`--group=functional`, or `--group=all`. The default is `--group=all`:

| Group | Runs |
| --- | --- |
| `compiler` | Compiler and offline checks. Sets `BURST_SIMULATE=0`; skips Mantis and simulator lookup. |
| `functional` | Mantis cycle-gated cases and the selected ModelSim/Questa functional gates. |
| `all` (default) | Both groups. |

CI runs the Verilog component suite, compiler-only checks, and functional
ModelSim gates as three separate jobs. The compiler job does not require the
Mentor runner; both functional jobs use ModelSim/Questa. Verilator is not used
for this qualification.

The AXI-burst Mantis cases use a 1,000,000-cycle generated-testbench watchdog and
a 30-minute per-command timeout. The cycle bound is about 15 times the measured
66,563-cycle scalar fallback case; it also covers the 9,221-cycle read case with
128-cycle memory latency. Mantis and Bambu accept later caller-provided
`--timeout` and `--commonargs=--max-sim-cycles=...` overrides. These bounds are
local to this regression and do not change the general Mantis or Bambu defaults.

The recurring functional group uses ModelSim/Questa for the read and write
engine suites, generated-kernel and wrapper-RID simulations, and Verilog
portability checks. The read-engine suite uses four independent output trees;
each tree has a private ModelSim work library and serial scenarios. The
wrapper-RID simulation reuses RTL generated by its kernel test. The write-engine
gate dispatches profiles, parameter rejections and mutation checks through its
own bounded pool. `bambu_axi_burst.sh -j N` bounds the helper pool and, when
Mantis is selected, its parallelism too. The main regression defaults
`BURST_WRITER_GROUP_JOBS` to 8 and limits it to the outer `-j N` value. Direct invocation of
`panda_regressions/verilog/axi_burst/rtl_tests/run_write_burst_engine.sh` still requires
`BURST_WRITER_SIM_OUTSIDE_SANDBOX=1`; the main regression supplies that guard
when dispatching the gate. The standalone writer runner defaults its group
limit to 12; set `BURST_WRITER_GROUP_JOBS` to tune either mode.

The functional group also runs
`panda_regressions/verilog/axi_burst/rtl_tests/run_default_duplex_reduction_modelsims.sh`,
which compiles and simulates default and explicit duplex profiles with a live-out
reduction. Its provenance, generated RTL, logs and ModelSim work library are
kept under `<out_root>/rtl-default-duplex-reduction` when artifacts are retained.

## `m_axi` burst contract

Burst analysis is enabled by default. `m-axi-burst=0` disables it, while the
old `experimental-m-axi-burst` parameter is rejected with a rename diagnostic.
An interface declared with `mode=m_axi` is analyzed automatically; no
`max_read_burst_length` or `max_write_burst_length` attribute is required to
activate the analysis. If no maximum burst length or outstanding count is
specified, each direction defaults to 16 burst beats and 16 outstanding
transactions, matching Vitis HLS defaults. `max_read_burst_length` and
`max_write_burst_length` accept integers from 1 to 256. Read and write FIFO
depths can be set explicitly as powers of two from 1 to 4096 beats; otherwise
the compiler derives a FIFO depth from the selected burst and outstanding
profile. Outstanding and FIFO profile attributes require `mode=m_axi`; legacy
maximum burst hints on other interface modes are warned and ignored.

Analysis outcomes are recorded in the Bambu log: selected defaults and
overrides, invalid or unsupported cases, and optimizations that activate or
fall back to the legacy single-access implementation. Unsupported or unproven
accesses remain on that implementation; selected same-base duplex cases use a
runtime range guard, while unsupported nested shapes conservatively fall back.
The compiler-only `run_default_burst_tests.sh` checks these default profiles,
explicit opt-out, overrides, FIXED-device fallback and diagnostics.

Recognition is deliberately narrow: accesses must match supported counted
loops over contiguous 32-bit elements with a zero-based, unit-step induction
and a four-byte indexed address. Effect, alias and control-flow checks decide
whether a request is safe. Unsupported or unproven cases keep the legacy
single-access implementation; selected same-base duplex cases use a runtime
range guard, while unsupported nested shapes conservatively fall back.

The standalone `panda_regressions/verilog/axi_burst/rtl_tests/run_axi_width_contract.sh` checks reader data widths
of 8, 16, 32, 64, 128, 256, 512 and 1024 bits (ARSIZE 0 through 7), and rejects
2048- and 4096-bit reader widths. The current writer cell accepts 32-bit data
beats only.

The `latency` interface attribute is scheduling metadata for `m_axi`, not a
simulation-memory delay. Equal explicit values are merged per bundle, conflicting
explicit values are rejected, and omitted values resolve to zero. Simulation
stimulus delay is controlled separately with `--mem-delay-read` and
`--mem-delay-write`.

For MDPI simulation, pointer extents must be known from source array/reference
metadata, `--tb-param-size`, or testbench `m_param_alloc`. An unknown or zero
extent fails preflight rather than guessing a size; scalar pointer outputs in a
custom C testbench need an explicit allocation.

Unexpected AXI faults in the selected simulation models produce a named
diagnostic and stop the run. Intentional containment/reset tests select
continuation explicitly with `+AXI_BURST_EXPECT_FAULT`. These diagnostics are
simulation-only: they do not add a synthesized fault/status interface or promise
hardware recovery from AXI errors.

The logging checks exercise large binary streams, producer and log-writer errors,
and inherited simulator logging without relying on the system `tee` implementation.

The recurring regression wrapper also runs the offline unit checks for the
write-artifact checker and write-engine extractor. The broader write compiler
matrix and generated-kernel G2 simulations remain opt-in development suites and
are not added to CI. Run them together with a fresh output directory and the
exact installed Bambu executable:

```sh
bash panda_regressions/hls/bambu_axi_burst/run_write_development_tests.sh all \
  /path/to/install/bin/bambu out_axi_write_development_run
```

Use mode `offline`, `compiler`, or `g2` to run one part. Compiler mode runs the
write-profile compiler matrix and frontend compatibility checks. G2 mode
compiles and simulates the three supported generated tops; run it outside the
sandbox with `BURST_G2_SIM_OUTSIDE_SANDBOX=1`. The aggregator refuses an existing
output path and retains per-suite output under it. Historical F1b G2 pass
markers do not qualify the current runner/script revision; G2 remains unqualified
until the current aggregator is run successfully.

The entry point intentionally does not run the broader `all` or `burst-type`
compiler-runner modes: they duplicate Mantis coverage.
By default all durable output is placed in `./out_bambu_axi_burst`, relative
to the caller's current directory. The script refuses to run if that path (or
an explicitly selected `-o/--output` path) already exists, including a
dangling symlink. Use a fresh path for each run. In the functional and all
groups, Mantis writes cases/report under `<out_root>/mantis`; temporary files
use `<out_root>/tmp`. Internal mock checks and auxiliary Python suites write to
per-suite `out_<suite>` children under `<out_root>`. No run artifacts are
created outside `<out_root>`.

Standalone shell runners default to a fresh `./out_<test>` directory in the
launch directory; an explicit relative output path is resolved from that same
directory. Python offline suites create their own `out_<suite>` directory under
`BURST_TEST_TMPDIR` when set, or under the launch directory otherwise. The main
regression sets that parent to its selected output root, keeping helper outputs
and temporary files beneath the same run.

Like sibling classic regressions, the default behavior cleans generated
intermediates after all gates pass, while preserving the `out_` root, report,
and, when Mantis runs, its canonical logs/results (`execution.log`, `timeout.log`,
`failure.log`, `return_value`, `bambu_results.xml`). On failure diagnostics
are retained. Pass `--no-clean` to retain successful-run intermediates too.
Mantis writes its configured cases under
`out_bambu_axi_burst/mantis/AXI-BURST/`; its suite report is in that Mantis
output directory. The compiler group does not create this tree.

The cycle expectation table contains measured read and writer signatures. The
three writer cases were simulated externally with ModelSim, checked against the
write-specific RTL profile, and passed the golden-data/canary testbench. Their
recorded cycle counts are regression signatures for the documented model
configuration, not a physical timing or general performance claim.
Auxiliary job logs are in `<out_root>/jobs/` when outputs are retained with
`--no-clean` or after a failure; successful default-clean runs remove them.

Pass `-j N` or `--parallel N` (also `-jN`, `-j=N`, and `--parallel=N`) to set
the maximum parallelism; the default is the `J` environment value or 1. Mantis
`-o DIR` or `--output DIR` (including `--output=DIR`) selects another output
root; repeated output options use the last value.
Repeated parallelism options use their minimum value, matching Mantis. In the
functional or all group, Mantis runs first using that limit internally. The
selected helper suites then share a bounded pool of at most N jobs. The
generated-kernel test and its wrapper-RID check remain one serial job because
the latter consumes the former's RTL. On failure, no more jobs are launched;
all already-started jobs are awaited and their logs are retained under
`<out_root>/jobs/`.

`--restart` in the functional or all group resumes Mantis in the existing
output root and runs the cycle gate against retained results. After that gate
passes, helper outputs go to a new `<out_root>/out_helpers_restart.*` directory
so earlier evidence is preserved. Compiler-only restart uses a fresh
`<out_root>/out_helpers_compiler.*` helper directory. Restart requires retained
outputs; a successful default-clean run removes generated RTL and needs a fresh
output root because the wrapper does not cache or reconstruct those artifacts.
