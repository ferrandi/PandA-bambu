# BS-010 — Implement PAF Wire Identity and Canonical Form

## Objective

Implement the minimal identity substrate required by every later PAF contract, graph, artifact, route and Evidence Package.

## Implement

- LogicalId
- RevisionId
- TypedDigest
- canonical byte encoding
- namespaces and schema/version identifiers
- extension and migration envelopes
- deterministic equality, comparison and errors
- valid and adversarial conformance vectors

## Invariants

1. Logical identity is distinct from immutable revision identity.
2. Digests are typed and domain-separated.
3. Canonical encoding is deterministic.
4. Key ordering does not alter canonical bytes.
5. Unknown versions/extensions have explicit behavior.
6. Human-readable strings are not canonical bytes.
7. Identity cannot depend on path, branch, display name or current time.
8. PAF and SODA-EVOLVE namespaces are supported without coupling.

## Non-goals

No runtime adapters, durable state, planning, routing, MCP/A2A, GUI or EDA behavior.

## Acceptance criteria

- AC-1 separate logical/revision identities;
- AC-2 typed algorithm/domain digests;
- AC-3 deterministic canonical bytes;
- AC-4 numeric, Unicode, null, binary, lists and nested objects defined;
- AC-5 invalid/ambiguous forms rejected deterministically;
- AC-6 extension/migration envelopes tested;
- AC-7 golden valid/adversarial vectors;
- AC-8 two independent readers/verifiers or implementations validate vectors;
- AC-9 compatibility/invariants documented.
